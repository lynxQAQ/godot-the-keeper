> 本文档用于规划游戏开发的里程碑和任务拆解，遵循线性开发原则，一步一脚印推进项目。
> 
> **注意**：此规划主要用于vibe coding，着重考虑里程碑划分和各里程碑内的Task拆解。
> 
> **使用说明**：每个任务（Task）都应该：
> - 可以独立实现和测试
> - 有明确的输入输出定义
> - 包含必要的技术实现要点
> - 符合Godot/GDScript开发规范
> - 遵循项目命名规范（文件夹英文，文件中文）

## 详细里程碑规划

### M1: 项目基础框架搭建

**目标**：建立项目基础结构，实现核心管理器和数据层框架

**前置条件**：无

**任务列表**：
- [X] **T1.1** 创建Godot项目基础目录结构
  - 创建 `scripts/` 目录及其子目录：`core/`, `systems/`, `managers/`, `data/`, `utils/`
  - 创建 `scenes/` 目录及其子目录：`worlds/`, `ui/`, `entities/`, `cards/`
  - 创建 `resources/` 目录及其子目录：`data/`, `configs/`, `prefabs/`
  - 创建 `autoload/` 目录用于单例管理器
  - 创建 `data/` 目录用于数据文件（JSON、CSV等）
  - 创建 `assets/` 目录用于美术资源（sprites、sounds等）

- [X] **T1.2** 实现Constants常量定义类
  - 创建 `scripts/core/Constants.gd` 单例（autoload）
  - 定义游戏阶段常量：`PREPARATION_PHASE`, `COMBAT_PHASE`, `SETTLEMENT_PHASE`
  - 定义网格类型常量：`GRID_TYPE_UNEXPLORED`, `GRID_TYPE_EXPLORED`, `GRID_TYPE_MAZE`
  - 定义构造体类型常量：`CONSTRUCT_TYPE_ENTITY`, `CONSTRUCT_TYPE_VIRTUAL`
  - 定义真理要素状态常量：`TRUTH_STATE_ACTIVE`, `TRUTH_STATE_SLEEPING`, `TRUTH_STATE_EXTINCT`, `TRUTH_STATE_SUBLIMATED`
  - 定义检定结果常量：`CHECK_RESULT_CRITICAL_SUCCESS`, `CHECK_RESULT_SUCCESS`, `CHECK_RESULT_FAILURE`, `CHECK_RESULT_CRITICAL_FAILURE`
  - 定义默认数值常量（准备阶段时长、初始资源等）

- [X] **T1.3** 实现基础工具类（Extensions、Helpers）
  - 创建 `scripts/utils/Extensions.gd`，实现常用扩展方法
    - `Vector2i` 扩展：网格坐标转换、相邻网格获取
    - `Array` 扩展：随机选择、权重选择
    - `Dictionary` 扩展：深度合并、安全获取
  - 创建 `scripts/utils/Helpers.gd`，实现工具函数
    - 数学工具：距离计算、角度计算、范围检查
    - 随机工具：权重随机、正态分布随机
    - 字符串工具：格式化、本地化支持

- [X] **T1.4** 实现信号总线（SignalBus）
  - 创建 `autoload/SignalBus.gd` 单例
  - 定义全局信号：游戏阶段切换、资源变化、构造体生成、调查员状态变化等
  - 实现信号注册和发射机制

- [X] **T1.5** 实现数据层基础框架
  - 创建 `scripts/data/BaseData.gd` 基类（Resource）
  - 实现数据序列化/反序列化接口
  - 创建 `scripts/data/DataManager.gd` 用于数据加载和管理
  - 实现JSON数据加载和缓存机制

- [X] **T1.6** 实现日志系统
  - 创建 `scripts/utils/Logger.gd` 单例
  - 实现分级日志（DEBUG、INFO、WARNING、ERROR）
  - 支持日志文件输出和控制台输出
  - 实现日志过滤和格式化

**验收标准**：
- 项目目录结构清晰，符合规范
- 所有常量定义完整，易于扩展
- 工具类功能完整，可独立测试
- 信号总线正常工作，可跨系统通信
- 数据层可以加载和解析JSON文件
- 日志系统可以正常输出和记录
